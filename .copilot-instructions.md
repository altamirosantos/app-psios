- Este projeto utiliza React Native para o desenvolvimento de um aplicativo que auxilia os usuários a lidarem com suas emoções e sentimentos utilizando metodologias da psicologia com abordagem na TCC e recursos audio visuais, de comunicação e IA.
- O código deve seguir as melhores práticas recomendadas pela comunidade React Native.
- O uso de hooks do React é incentivado para gerenciar estado e efeitos colaterais.
- O estilo do código deve ser consistente, utilizando ESLint e Prettier conforme configurados no projeto.
- Componentes funcionais são preferidos em relação a componentes de classe, a menos que haja uma justificativa clara para o uso de classes.
- Os nomes dos arquivos devem ser descritivos e seguir a convenção PascalCase para componentes React.
- Comentários devem ser usados para explicar trechos complexos de código, mas o código deve ser autoexplicativo sempre que possível.
- As dependências do projeto devem ser mantidas atualizadas, e o uso de bibliotecas externas deve ser justificado.
- Testes unitários e de integração devem ser escritos para componentes críticos do aplicativo.
- Acessibilidade deve ser considerada durante o desenvolvimento para garantir que o aplicativo seja utilizável por todos os usuários.
- O desempenho do aplicativo deve ser monitorado, e otimizações devem ser feitas conforme necessário.
- Documentação clara deve ser mantida para facilitar a colaboração entre os membros da equipe.
- O app utiliza como base de dados o supabase disponibilizada em @/lib/supabase
- O arquivo schema-avaliacao.json possui a estrutura do banco de dados utilizado para armazenar as respostas do formulário de autoavaliação.
- O arquivo example-respostaFinal.json possui um exemplo de respostas preenchidas para o formulário de autoavaliação.
- O arquivo prisma/schema.prisma define o modelo de dados utilizado pelo Prisma para interagir com o banco de dados Supabase.
- Arquivos de documentação do sistemas estão na pasta docs/

## Rules e Skills

### Rules (Padrões e Convenções)

O projeto possui **rules** em `.claude/rules/` que definem padrões obrigatórios:

- **`dark-mode.md`** - Sistema de Dark Mode
  - 📐 Define cores (light/dark) e suas variações
  - 📋 3 opções de implementação (rápida, completa, com helpers)
  - 💅 Padrões de design (estrutura, regras de cor, pro tips)
  - 📚 Snippets prontos para copiar/colar (cards, input, modal, lista, etc)

- **`api-usage.md`** - Integração com API Supabase
  - 🎯 Cliente Supabase centralizado (`lib/supabase.ts`)
  - 📊 Schema Prisma (20+ modelos de banco de dados)
  - 📚 5 padrões de implementação (CRUD, relações, autenticação, storage, classe)
  - ✅ Checklist para novo service
  - ⚠️ Anti-patterns comuns e como evitar

### Skills (Processos e Como Fazer)

O projeto possui **skills** em `.claude/skills/` que descrevem como executar tarefas:

- **`migrate-dark-mode.md`** - Migrar uma tela existente para Dark Mode
  - ✅ Checklist passo a passo (10 fases)
  - 📖 Exemplo prático de migração completa (antes/depois)
  - 🔍 Validação (lint, testes em light/dark, acessibilidade)
  - ⚠️ Armadilhas comuns e como evitar

### Como Usar

1. **Implementar Dark Mode em NOVA tela?** 
   → Consulte `.claude/rules/dark-mode.md` (padrões + snippets)

2. **Migrar tela EXISTENTE para Dark Mode?** 
   → Use `.claude/skills/migrate-dark-mode.md` (siga o checklist)

3. **Criar novo service para API Supabase?** 
   → Consulte `.claude/rules/api-usage.md` (5 padrões + checklist)

### Como Adicionar Novas Rules e Skills

Para adicionar novas rules e skills no futuro:

1. **Rule**: Criar arquivo em `.claude/rules/nome-da-rule.md`
   - Contém PADRÕES e CONVENÇÕES permanentes
   - Não contém atividades, prioridades ou tarefas específicas
   - Exemplo: `dark-mode.md`, `naming-conventions.md`, `component-patterns.md`

2. **Skill**: Criar arquivo em `.claude/skills/nome-da-skill.md`
   - Contém PROCESSOS e CHECKLISTS passo a passo
   - Descreve COMO FAZER uma tarefa específica
   - Exemplo: `migrate-dark-mode.md`, `setup-authentication.md`, `deploy-to-production.md`

3. **Atualizar este arquivo** (`.copilot-instructions.md`) com referências às novas rules/skills
